# Milestone 0: foundation (plan)

- Status: plan approved by the author on 2026-10-29
- Target: November 2026
- Done when: CI is green on an empty core with one passing test, on every Postgres version in the matrix.

## What gets built, in this order

Each step is one small commit with passing `npm test` and `npx tsc --noEmit`.

1. **Project skeleton.**
   - Root `package.json`: the published `keepwell`, `"type": "module"`, `engines.node >= 24`, version stays `0.0.1`, nothing is published.
   - `.nvmrc` with `24`.
   - `tsconfig.json`: strict, `erasableSyntaxOnly`, `rewriteRelativeImportExtensions`, `outDir: dist`.
   - Folders from CLAUDE.md §11. Each package gets an `src/index.ts` with a one-line header comment. `packages/core` exports one function with one passing test.
2. **Tests.**
   - Unit tests in `packages/*/test/` run with `node --test`.
   - Integration tests in `test/integration/` need `DATABASE_URL_TEST`. In M0 there is one test: connect, read `server_version`, create and drop a table. It uses `pg`, which is pre-approved.
   - Locally, integration tests are skipped with a clear message when no database is configured. In CI, a missing database is a failure.
3. **`docker-compose.yml`.** `postgres:18` (record 0011) with a health check and a named volume, on port `${KEEPWELL_PG_PORT:-5432}`.
4. **Check scripts** in `scripts/`. Plain Node, no dependencies, each under 100 lines:
   - `check-deps`: direct runtime dependencies ≤ the ceiling, and none outside the approved list.
   - `check-imports`: `packages/core` imports nothing outside itself; `core` and `runtime` import no model or hosting SDK; packages import each other only through their index (ADR 0007).
   - `check-words`: the banned words from §2.7 in README, `docs/` and refusal templates, with an allowlist file.
   - `check-file-length`: no source file over 400 lines without a decision record.
   - `check-pack`: `npm pack`, install the tarball in an empty folder, run `npx keepwell --version` and import the library (ADR 0007). M0 ships a minimal `keepwell --version` command for this.
5. **CI** (`.github/workflows/ci.yml`).
   - Jobs: typecheck, unit tests, checks, pack, and integration tests on Postgres 15, 16, 17 and 18 as service containers (record 0011).
   - Node 24. `permissions: contents: read`. Actions pinned to commit hashes.
6. **Repo files.**
   - `SECURITY.md`, using GitHub's private vulnerability reporting as the disclosure channel (record 0012; I switch it on for the repo).
   - `docs/decisions/0001` (already written).
   - README keeps three lines, plus the link to issues that §7 asks for.
7. **Report** in this file, following CLAUDE.md §8.

### Needed before milestone 1a (formats and security)

7. **`duplicate` leaks records to actors without permission (record 0009).**
   - Load (step 5) runs before permission (step 6).
   - *Suggestion:* check permission first.
8. **Idempotency (record 0009).**
   - Two concurrent retries with the same key can both run, and keys have no owner.
   - *Suggestion:* scope keys to (actor, intent) and insert the key inside the write transaction.
9. **People and grants (record 0009).**
   - Deny-by-default, read literally, blocks people acting in-process, because they have no grant.
   - *Suggestion:* grants apply to agents and jobs, and people get what the declaration allows people.
10. **Personal-data erasure vs. the append-only audit log (record 0006).**
    - §4.3's trigger rejects every `UPDATE`, so erasure can't edit audit rows.
    - §3.1 allows the erasure decision to wait until milestone 8, but the audit shape is frozen from milestone 1b.
    - *Suggestion:* decide it now, together with the audit shape (record 0005).
11. **Standing rules: milestone 1a or 1c?**
    - §5 says the 1a core does pipeline steps 6–13. That includes step 11, standing rules, which are scheduled for 1c.
    - *Suggestion:* the core evaluates standing rules in 1a. It is pure logic that receives the matching rows as input. 1c adds the table, editing and audit.
12. **MCP tool names can collide (record 0002).**
    - `bank_account.x` and `bank.account_x` both become `bank_account_x`.
    - A transition named `get` or `search` clashes with the built-in tools.
    - *Suggestion:* `check` refuses collisions and reserved names.

### 1. In plain language

The repository is now a working TypeScript project: one package, Node 24, strict types, and tests on Node's own test runner. Every push runs CI. It checks the types, the unit tests, the dependency limit, the import boundaries, banned words and file length. It also checks that the package installs and that its `keepwell` command runs. Integration tests run against Postgres 15, 16, 17 and 18. `docker compose up -d` gives a local Postgres, and security reports have a private channel on GitHub.

- [0007](../decisions/0007-packaging-one-package.md), accepted: one package with no workspaces. The build mirrors `packages/` into `dist/`.

Small choices that are cheap to change and have no record:
- **TypeScript 7.0.2**, the current release. It installs one prebuilt compiler binary for the platform.
- **Versions:** development dependencies are pinned exactly. `pg` is a caret range, so users' apps can share one copy.
- **Build path:** the build output is `dist/<package>/src/…`, so the command finds `package.json` at the same relative path from source and from the build.
- **CI install:** CI installs with `--ignore-scripts`.

### 8. Deviations from CLAUDE.md

- `CLAUDE.md` isn't in the repository. This was the author's decision; it is git-ignored, and `check-pack` refuses a tarball that contains it.
- There are no npm workspaces (0007), and no `tsx` (0008).
- The dependency ceiling is 6 (0010).
- Postgres 18 was added (0011). `docker-compose.yml` uses 18 rather than the 17 named in this plan.
- `spec/`, `skills/` and `examples/` don't exist yet. Git can't hold empty folders, so each will appear with its first content.

### 9. What is not done or fragile

- **Import check:** `check-imports` finds imports with a pattern, not a parser. Text in a comment can trigger it, which errs on the strict side. An `import()` with a computed name isn't checked.
- **Words check:** `check-words` matches whole words. "Guardrails as a lead word" can't be judged by a script, so "guardrails" is banned outright in user-facing text.
- **Action updates:** the GitHub Actions are pinned to commit hashes and need updating by hand. Nothing updates them automatically yet.
- **Duplicate CI runs:** a branch with an open pull request gets two CI runs, one for the push and one for the pull request.
- **Thin integration test:** it only proves the connection and a round trip.
- **npm page:** the description on npm still says "Placeholder", and npm's readme field stays empty until the next publish. Nothing was published in this milestone.
